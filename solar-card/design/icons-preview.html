// 这次"对齐"改了什么

问题：五枚图标 viewBox 各不相同（41×50 / 44×49 / 42×42 / 42×40 / 44×44）， 我又给每项各写了一套 w/h，结果渲染出来的实际大小与纵向基线全在飘—— 最小的 save 只有 13.9 宽，最大的 log 有 16.8，而地图因为画布留白只占了 9.3 高，看着就"小一圈"。
改法 ①：viewBox 全部改成紧贴路径，不塞空白画布 —— 这样"渲染尺寸"才等于"图形尺寸"。
改法 ②：统一渲染高度 16px，宽度按各自宽高比（13.54 / 14.05 / 16.03 / 16.8 / 17.07 / 17.07）。
改法 ③：左栏给图标一个固定 19px 的槽，槽内居中 —— 六枚的中线一致， 文字左边缘也就对齐了（这是"位置对齐"的关键，之前文字起点会随图标宽度左右跳）。
改法 ④：地图重画为 32×30（宽高比 1.067），与 log 的 1.050、data 的 1.002 同档 —— 上一版是 38×24（1.58），本来就是"矮胖"的，塞进这排里必然显小。
顺带：终端那枚原来用文字符号 ⌨ 占位，字号无法和矢量对齐， 我按同一套规格自制了一枚（窗口 + ❯ 提示符 + 光标条），六项现在全是矢量图标。

// 左栏收起 / 展开（D28）

行为：默认 52px 只露图标，鼠标移入（或键盘 Tab 聚焦）展开到 168px 显示文字，移开自动收回。
实现：纯 CSS（:hover + :focus-within），不加 JS 状态，键盘用户同样可达。
不动内容：导航是 52px 的栅格列，展开时**超出自己的列、覆盖在内容之上**（z-index:30）， 所以正文不会被推着重排；影子随展开变强，读起来就是一个抽屉。
手机端：没有 hover，底部横条常驻显示图标 + 文字，不做收起展开。
